# 真实对话回归与数值条件补测

验收日期：2026-11-01。本轮按 xerina 要求测试与定位，不修改业务逻辑、
模型配置、画像、配方或数据断言，不重跑失败用例覆盖首轮证据。

## 范围

- 使用既有 Web 5178/API 8006/MCP 8012、`qwen-plus`、BGE、
  PostgreSQL、Redis、Qdrant 和一个独立聊天 Worker。
- 运行固定 `ingredient-dialogue-2026-10-30-v1` 数据集，
  共 40 场景、57 轮，涵盖必含/任选食材、别名、替换/追加/清除、
  换一批、过敏冲突、未知价格/准备时间及无候选。
- 默认演示用户画像保持原样；补测使用独立用户与新会话。
  测试会留下会话、任务、消息与 Trace，不写餐单或修改既有业务记录。
- 另行只读核查每轮持久化结果、条件清空、换菜排除、
  实际源配方的食材、接触过敏原与整菜营养边界。
- 数值补测为四类条件分别取消、取消后换菜、重新指定、
  否定取消，以及重新建立 HTTP 客户端后恢复与续聊。
  新客户端检查不是 API/Worker 重启验收。

## 已观察问题

### P1：无本轮检索仍能输出不符菜名

`ingredient-39` 第二轮“取消食材限制”中，Planner 返回 `complete=true`、
空工具列表，没有本轮画像/反馈/检索。Recommendation 使用旧候选 ID 生成了三道不同的菜：

| ID | 模型展示 | 此 ID 对应源菜谱 |
| --- | --- | --- |
| 1034 | 香煎三文鱼配藜麦蔬菜沙拉 | 凉拌鸡丝 |
| 1048 | 番茄牛腩炖土豆 | 葱煎豆腐 |
| 1043 | 豆腐菠菜味噌汤 | 皮蛋豆腐 |

三个展示项均无热量、蛋白质、范围、引用和警告，却以 `completed` 输出。
Trace：`4684f629-0b85-42ff-b4f2-292bece4ba0c`。

定位链路：

- `src/nutripilot/application/chat_service.py:197` 将上一轮候选 ID 带入新轮，
  但新轮工具结果为空。
- `src/nutripilot/agent/routing.py` 在没有待执行调用时直接进入生成，
  不要求本轮已经完成推荐所需读取。
- `src/nutripilot/agent/grounding.py:324` 的 `_ground_nutrition` 在缺少数据时原样返回响应，
  推荐路径也可能进入此分支，没能消除无依据卡片。
- `src/nutripilot/agent/nodes/output.py:29` 与
  `src/nutripilot/safety/guards.py:107` 只凭允许 ID 过滤，
  无法保证该 ID 的本轮菜名、营养和来源一致。

应优先修复：无本轮可信事实时不发布推荐；生成卡片必须从本轮事实重建，
旧候选仅供会话引用，不能单独作为发布依据。还需补充不依赖模型重现的确定性回归。
本轮仅观察现有普通用户流程，没有修改校验或增加新的模型调用复现。

### P1：未知食材被改成普通推荐

`ingredient-19` 的“午餐想吃龙肉”被保存为 `food_name`，
`required_ingredients` 却为空。最终返回清蒸鲈鱼、凉拌鸡丝、黄瓜炒肉，
没有说明未收录或请求澄清。

Trace：`9d13c3b1-e8a8-495a-b09e-9500eaec627a`。

定位：Intent 的食材/菜名分类与检索约束没有闭环。
`src/nutripilot/agent/agents/intent.py` 的 `_resolved_slots` 保留菜名，
但 `src/nutripilot/agent/grounding.py` 仅在存在同名候选时优先选中；
同名候选不存在时仍允许返回其他候选。需要保留用户明确要求的对象，
无法匹配时说明未收录或澄清，不静默放宽。

### P2：必要前置读取不稳定

`ingredient-25` 第二轮“换一批”只规划 `search_meals`，
没有读取本轮画像，工具边界正确阻止未校验画像的检索，
最终任务为 `failed`、错误码 `PROFILE_REQUIRED`。

Trace：`145bbd96-4fb2-4f1e-b15d-839d1a808538`。

定位：`src/nutripilot/agent/agents/planner.py` 在提示词中要求前置读取，
但 `_validate_tool_plan` 只检查工具白名单与参数 Schema，
不强制执行顺序。`src/nutripilot/agent/nodes/tool.py:135` 保留了必要的画像门槛。
后续应把必要前置读取变成确定性调度，不能删除此门槛解决失败。

另外三个场景在检索前未读取历史反馈：

| --- | --- | --- |
| ingredient-18 | 1 | `025d8abb-01a0-4cb1-8fef-93e7607db831` |

与上述未知食材、换菜失败、无事实生成一起，构成 6 项非天气问题。

### 评测口径与遗漏

- 数据集所有场景都强制调用 `get_weather_context`。
  当前 Planner 要求读取画像、反馈再检索，没有要求普通食材推荐必须查天气。
  只缺天气工具的失败与真实功能失败应分开报告；原始报告与断言保持不变。
- `src/nutripilot/evaluation/metrics.py` 的列表槽位比较采用子集检查：
  预期空列表时，残留非空列表也会通过。取消条件需另查准确的持久化值；
  `null` 也需区分字段不存在与显式取消。
- 原始场景未统一断言最终 `COMPLETED`，不能仅因意图或空候选断言通过
  就认定完成。独立核查同时检查实际任务状态与阶段。
- 原评测根据 ID 查询配方，不比较卡片名称、营养、来源；
  `ingredient-39` 因此只报工具断言失败。独立核查补查三个字段后发现不符，
  没有通过更改原报告“修正”通过数。
