# 推荐卡片与正文分工

日期：2026-11-02。

## 范围

按 xerina 要求保留推荐卡片，但理由放在回答正文，卡片只提供菜名、能量和营养组成。
不扩菜谱、不改变整菜口径、不新增 Agent、Worker、服务、依赖或数据库迁移。

## 实现

- `ChatView.tsx` 不再将 `reason`、`recommendation_reason` 或 `description` 映射为卡片理由，
  删除理由段落和目标标签；显示菜名、整道菜估算能量、蛋白质、碳水、脂肪和估算口径。
  警告与来源仍在回答区域，未为精简卡片而删除。
- 原 `MealRecommendation` 只有能量、蛋白质，新增可选 `carbohydrates_g`、`fat_g`。
  `ground_recommendation_facts` 与能量一样从工具事实覆盖这两个字段，模型传入数值不能背书。
  前端补上顶层 `carbohydrates_g` 的已有单位别名；沿用原区间格式和非负字段验证。
- 未知营养保持 `None`，前端不显示该指标，不补为零；真实零值保留。
  旧会话没有这两个字段也可恢复，不从当前配方回填或改写历史记录。
- `recommendation-v13` 明确要求在 `message` 中解释选择，内部 `reason` 仅保存与正文一致的简要依据，
  供历史上下文和后续追问使用。没有删除公共响应里的旧字段，以免破坏已有调用方和会话恢复。
- 规范化事实模板在有可靠理由时把理由写入正文，审核或预算降级也不依赖卡片承担解释。
  最终安全过滤、摘要绑定、身份隔离、幂等和持久化机制保留。
