# PR #1 CI 故障修复（2026-11-12）

## 远程故障

PR：<https://github.com/roman1115/nutripilot/pull/1>。
修复前提交为 `5f23fc23a6d66468e17bd246bd0b0865c359f139`。
GitHub Actions 运行 `42978144435` 中前端通过，浏览器失败，
后端 pytest 超过六小时后被平台取消；PR 没有合并冲突。

浏览器失败于 `scripts/verify_web.py` 的过敏原文案断言。
当次推荐“白萝卜丝清汤”，数据未标注过敏原，页面正确显示未知风险提示，
脚本却只接受“餐食记录标注的过敏原”。携带随机验收编号的检索输入
可能选择不同菜品，因此不能假设每次推荐都有已标注过敏原。

后端默认并发为四个任务。归属锁保护检查点写入，
使用 `asyncio.to_thread` 分别进入、退出同步锁。
双核环境默认线程池容量较小，多个检查点等待同一把锁时占满线程，
释放锁的任务无法执行，造成死锁。本机大线程池未稳定复现；
Linux 容器将 `os.cpu_count()` 模拟为 2 后，原代码稳定停在首个持久并发测试，
诊断堆栈显示线程池线程全部等待 `ChatTaskStore.transaction`。

同轮 Linux 检查还暴露关停顺序错误：后台评测仍在提交数据库操作，
任务存储已关闭，出现 SQLite 读写与关闭并发。新增测试在修复前明确失败。

## 修复

- 归属锁退出使用 AnyIO 已有的线程池及独立容量限制，
  避免与等待锁的默认线程池竞争；锁持有区间、执行版本检查及取消保护保留。
- 先取消并等待后台评测，再停止 Worker、关闭任务存储。
- 持久任务异步测试中的同步存储访问改为 `asyncio.to_thread`，
  防止事件循环阻塞等待由自身异步流程持有的锁。
- 浏览器校验同时覆盖已标注及未标注状态，仍必须显示交叉接触提醒；
  失败保存截图和 HTML，CI 同时上传应用日志。
- CI 后端输出具体测试名及一分钟诊断堆栈；
  后端和浏览器任务各设十五分钟上限，避免再次消耗六小时。
- Linux 仿真运行发现模型取消测试原 20 毫秒预算过短，
  改为 200 毫秒并明确断言模型启动和取消；业务默认时限未改变。
