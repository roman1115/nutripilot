# 回答自主性与事实边界核查

日期：2026-11-03。结论：正常正文由回答 Agent 自主生成的链路已生效，事实语义与安全边界仍未通过本轮验收。仅核查实现并运行测试，没有修改回答、审核或安全业务代码。

## 代码核查

- 当前回答版本为 `recommendation-v19`，生成输入包括当前问题、槽位、历史展示对象及工具事实投影，没有 `verified_response` 模板正文。
- 推荐理由与比较正常调用回答 Agent 和审核模型；`canonical_why_answer` 与 `canonical_comparison_answer` 仍用于构造事实基线及失败降级，不再是跳过回答 Agent 的正常出口。
- `prose_issues` 检查来源、菜名/编号、数字和个人/医疗声明；审核通过后保存 Agent 原始 message/reason。最终事实摘要未变化且输出安全检查通过时，`apply_approved_answer` 恢复该正文。
- `ground_recommendation_facts` 仍规范化卡片菜名、营养和来源。安全过滤改变事实或审核/预算失败时，程序保留事实降级文案。这属于预期的保护措施。
- `AnswerReview` 仅返回 `supported` 和 `issues`，语义是否有据主要依赖模型判断；数值程序检查只能判断数值与单位是否见于证据，不能独立证明归属、适用条件或健康功效。

## 本轮验证

- 定向 pytest：86 项通过，范围为自然回答、回答安全、Agent 上下文和事实规范化四组测试；使用 Fake 网关，不代表真实效果。
- Qwen 可用性探测通过：输入 111、输出 5 Token。
- 真实入口 API 8006，Qwen/BGE/PostgreSQL/HTTP MCP 和独立 Worker 就绪。Trace 确认回答与审核实际使用 `recommendation-v19`，没有模型切换。
- 执行现有 `scripts/verify_conversational_answers.py`：12/12 轮任务完成、意图匹配，11/12 发布审核正文；6 张推荐卡片名称、四项营养、范围及来源与独立配方端点一致。
- 既有脚本严格结果为失败：空检索轮的未依据营养数字两次被拒绝，最终安全降级，未发布未审核文字。
- 主回归 56 次模型调用，输入 152,491、输出 6,849 Token；各轮等待耗时合计 192.63 秒。
- 另独立补测“想吃鸡胸肉，整道菜不超过600千卡”：仅返回凉拌鸡丝一张卡片，正文为单数，审核正文确实发布。5 次模型调用，输入 9,847、输出 514 Token，14.29 秒。这一例不能证明所有数量措辞都正确。
