# 回答证据审核改造

日期：2026-11-03。实现版本：`recommendation-v31`。本记录区分代码实现、
固定反例审核、真实完整对话和人工语言质量，不将模型自评当作事实正确证明。

## 职责与实现

正常正文与推荐解释仍由 Agent 自主组织，程序不按主观词表或数量正则替换正常正文。
本轮沿用已有的一次审核、最多一次修订、事实降级、24,000 Token 和90秒整轮限制，
未增加独立 Agent、服务、依赖、数据迁移或配方数据。

- 审核单位覆盖每段正文及每个非空推荐理由；推荐描述按句号、分号和冒号进一步拆分，
  防止一个正确食材断言掩盖后续菜品的虚构做法。遗漏、重复、未知单位均拒绝。
- 具体菜品事实、排序优势与健康功效须绑定工具原文。历史生成正文和理由不进入审核证据。
  请求只能证明用户需求，展示列表只能证明对象及顺序，不证明排序优劣。
- 来源记录提供字段路径及原文。多行摘录必须逐行真实存在且顺序一致；
  不接受拼接不存在的字段、改写原文或捏造记录编号。
- 对影响结论的来源条件，审核须同时提供来源摘录与正文对应摘录；
  正文摘录为空或实际不存在时，程序拒绝。来源有条件不等于正文保留了条件。
- 数量由模型提取正文原句、数量范围及对应对象，程序与安全筛选后的卡片编号或历史展示编号
  比对；拒绝虚构、重复编号以及无效范围。不用数量词表或数量正则拦截正文。
  单指三道中的一道允许选取对应编号。语义提取仍有误判/漏提取风险。
- 安全的定性食材常识、烹饪原理和可选补救建议无需假装来自收录配方；
  仍不允许绑定具体菜品的虚构功效、编造配方、无依据数值或危险建议。
- 修订获得被拒绝的原稿、问题原句和可用证据。不通过或预算不足时保留可靠事实降级，
  不发布未审核的模型文字。
- 审核对象先经过既有安全筛选；最终输出再次检查，并验证事实摘要未变化。
  原始数字、过敏原、食材、身份、写入确认、幂等和持久化保护继续保留。

审核材料同时考虑当前问题与实际草稿：无营养问题且草稿未提营养时不重复传营养表；
草稿引入营养说法时保留相应资料。剔除重复的收录说明，不删配方步骤与适用条件。
原始数字校验及最终安全过滤仍读取完整工具结果。

## 超时诊断与配置

前几轮真实完整对话发现审核调用超时、重试后预算不足。独立诊断中，审核用26.78秒
返回有效结构化结果，超过原25秒单次上限。默认 `MODEL_TIMEOUT_SECONDS` 调整为45，
`.env.example` 同步；整轮仍限制90秒及24,000 Token，没有增加修订次数。
审核解释改为简短说明，推荐理由允许留空以减少重复。

更长单次等待可能增加慢请求延迟。超时请求的实际消耗可能无法从提供方取得，
不放松耐久队列保守预留规则。已有显式环境变量继续覆盖默认设置。

## v31 最终完整对话

通过实际 API8006、独立Worker、Qwen/BGE、PostgreSQL与HTTP MCP运行12轮：

- 12/12轮任务完成、意图匹配；6/12轮发布审核正文。严格无降级门禁失败，
  这不是回答正确率或整体质量通过。
- 首轮推荐将食材匹配扩展为三处具体做法、口感与适用场景，逐句审核已拒绝；
  午餐轮正文称“五道”，实际三张卡片，程序基于模型提取的数量范围拒绝。
  两轮随后触达Token预算，保留可靠卡片与事实降级。
- “为什么第一道”首稿编造主料占比/优先原因，被拒绝并修订；最终说明仅展示顺序，
  不再编造排名。6张卡片名称、四项营养、区间与来源均与独立配方接口一致。
- 原理问题仍在第二稿引入历史配方、混合通用机理，被审核以来源不足拒绝，
  最终未给出有用解释。空检索回答两次扩充无依据数字，也进入事实降级。
- 人工复核补救回答仍混入不必要的历史步骤，且引用“5–7分钟”未完整保留来源条件，
  审核仍放行；另有菜谱意图的解释性建议与引用格式误拒。不能因固定反例通过而忽视这些问题。
- 本批53次模型调用，输入155,712、输出10,946 Token；这是本批统计，
  不含其他历史失败批次、固定反例回放和可用性探测。
- API/Worker已加载v31；重启前确认队列无活动任务，沿用原内部令牌及环境，
  未清空历史或数据卷。结束时API ready、Worker就绪、Web5178返回200。

结论：本轮完成逐段证据审核、条件摘录和结构化数量比对的实现与验证；
整体回答质量仍未通过验收。下一步应优先处理上下文与任务范围污染、
通用知识和具体配方事实的边界，以及审核/修订预算，不再靠堆叠关键词限制风格。

## 限制

引用存在和正文摘录真实只能证明可追溯性，不能证明引用蕴含结论、所有必要条件均被发现，
或配方原文本身就是安全保证。对象与语义判断仍依赖模型，可能误拒或漏判。
“审核通过/正文发布”是链路检查，不是整体自然回答质量达标。

本轮未改前端，未运行浏览器、前端构建、完整40场景、CookHero同题对照或压力测试。
本地 API/Worker 按空闲队列温和重启，沿用原配置、令牌及数据，未清空历史或数据卷。
