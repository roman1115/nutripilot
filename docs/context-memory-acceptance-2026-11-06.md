# 混合裁剪与 LangGraph 会话记忆改造验收

日期：2026-11-06。
范围：方案中的混合裁剪、图状态记忆、检查点恢复、基础历史召回及其调用方。
实现依据：[LangGraph 版设计](context-langgraph-design-2026-11-06.md)。
本次没有新增依赖、独立摘要表、后台摘要队列，也没有重启或部署现有服务。

## 1. 已实现

- `AgentState.messages` 采用原生 `add_messages`，稳定消息 ID 合并；
  新轮只更新本轮字段，承接摘要、高水位与原文，不再用默认空值清空记忆。
- 图增加记忆加载、准备、摘要、冻结、召回和终端收尾节点。
  普通调用、流式调用和持久 Worker 均使用同步检查点。
- 摘要节点读取旧摘要和连续完整前缀，校验结构、正文大小及来源 ID，
  一次节点更新返回新摘要、覆盖位置、版本及 `RemoveMessage`。
  失败保留原记忆，不推进覆盖位置。完整数据库原文不删除。
- 默认目标为最近6个完整轮次及当前未完成轮次；
  已归档且完整结束的轮次才可压缩，确认/拒绝关联组不按两条消息硬拆。
  预算严重不足时可减少保留轮次；未结束确认组阻止摘要越过该前缀。
- 意图、规划、回答共享冻结的双方原文、摘要与召回资料，
  当前输入仅出现一次；做法、通用问答、闲聊不再机械清空助手历史。
- 原文和摘要保留菜品展示顺序的来源元数据，只用于对象识别，
  不把历史助手建议升级为菜谱、营养或过敏事实。
- 复用现有工具字段投影，完全相同的投影结果去重，版本或内容有差异的资料保留。
  周餐单已验证计划的规划请求仅附候选标识，原始资料继续用于构建与写入校验。
- 完整模型请求（系统、schema、包装、反馈和 payload）使用同一构造函数计量和发送。
  主模型与备用模型共用显式 `MODEL_CONTEXT_WINDOW`，默认保守值32768，
  不按模型名称猜测。保留默认整轮24000 tokens和90秒。
- 准备阶段按80%占用评估，约60%为期望目标；轮数不独立强制摘要。
  比较预计输入节省与摘要成本，收益不足不调用摘要；
  本轮最多一次图内摘要，成功后重新计算剩余预算。
- 后续调用预算预测包含一次规划、一次回答的提示/schema和重复会话输入。
  这是初始预测，不保证未知工具循环次数；每个额外调用仍单独做硬预检。
  冻结阶段重新检查预算，不能因摘要后文本更短就忽略摘要自身消耗。
  生产模型报告的输入估算比例可以随状态承接，仍保留估算余量。
- 三种历史适配器提供稳定位置读取及有界关键词召回。
  默认当前会话，只有用户明确说其他/所有会话等才跨本人会话；
  生产适配器过滤回收站，位置读取继续检查所有权。
  召回最多一次、最多补判一次意图，携带来源、位置和明确的片段截断标记。
- 所有正常终端及取消/超时等异常终端使用同一无模型收尾规则，
  固定响应 ID、正文及创建时间；Worker 校验同一 run、图已结束和收尾标记后提交。
- 最终归档的暂时连接故障退避重试，不重新生成回答或将成功检查点覆盖为失败。
  旧格式的已结束检查点可以补收尾；模型外部调用仍可能因未保存结果而重复计费。
- 保留原有身份、任务归属、确认、工具幂等、回收站和整会话检查点清理。
  简单历史适配器也拒绝同 ID 不同内容，避免生产与演示行为不一致。
- 会话条件记录字段级来源、当前值及清空操作；已有槽位撤销机制继续生效。
  本次不把摘要写回用户长期画像。

## 2. 实际验证

最终代码执行 `NUTRIPILOT_TEST_EXTERNAL=1 .venv/bin/pytest --tb=short`：
653项全部通过，无跳过，1条警告，耗时68.30秒。
包含本地 PostgreSQL/Redis/Qdrant、API/Worker SIGKILL 恢复、
写入后检查点前中断恢复，以及新增会话记忆与归档重试测试。
相关102项回归另行通过；不将测试条目数表述为模型事实准确率。

- Ruff：本次修改的后端及测试通过。
- mypy：93个后端源文件通过。
- 前端 `npm run typecheck` 与 `npm run build` 均通过；无前端行为修改。
- `git diff --check` 通过；5份相关文档的85处本地链接、代码围栏及空白检查通过。
- PostgreSQL 专项：摘要和原文移除保存后关闭连接池，重新创建图与连接池，
  从下一个节点续跑，摘要版本和覆盖位置一致，完整历史仍保留。
- 持久 Worker 专项：注入一次最终归档连接故障后成功重试，
  无重复生成、无重复助手原文、仅一次完成事件。
- 基础测试：摘要失败/无效来源不移除；预算不足不启动摘要；
  摘要费用计入预算；新轮不覆盖摘要；完整双方历史与当前输入去重；
  消息位置、同 ID 冲突、召回身份/回收站及补判次数等。
- 真实模型摘要小样本：`qwen-plus` 一次摘要，输入538、输出120 tokens，
  保留“两人改一人、仅今天不加辣椒、不写永久偏好”及有效来源，
  覆盖4条消息。该结果是单样本验证，不是摘要准确率。
- 真实模型承接小样本：隔离内存环境两轮烹饪问答均 `COMPLETED`，
  零执行降级，各3次模型调用；第二轮基础上下文含上一轮用户与助手原文。
  两轮分别消耗5731、6587 tokens。本样本未触发自动摘要。

真实模型的普通回答仍出现无来源脂肪比例、补救建议因果依据不足等内容问题。
本次未重构已验收的直接回答链路，不能把“执行完成、承接成功”表述为事实准确。
摘要单样本、两轮承接、数据库恢复与 SIGKILL 过程验收分别计算，不合并成整体准确率。

## 3. 使用与兼容

核心路径：

```text
memory_load -> risk -> context_prepare -> [summarize] -> context_freeze
-> intent -> [history_recall -> intent] -> 原规划/工具/回答链路
-> memory_finalize -> END -> 消息/结果/run 归档事务
```

风险拦截不额外调用摘要；确认续跑承接原调用和确认状态，不作为新普通轮重置。
恢复同一 run 按检查点进度传 `None`，新普通轮使用增量输入。
检查点和最终归档不是跨表原子事务，依靠稳定 ID、执行归属及幂等提交恢复一致性。

部署时必须为主模型和备用模型配置两者都支持的上下文窗口；
默认32768是保守配置初值，不是对供应商最新窗口的声明。
不必迁移或复制现有原文；新增 `position` 只是历史读取模型的可选字段，
数据库原本已有稳定位置。旧近期文本拼接摘要仅作为兼容数据，不当作可靠滚动摘要。
原文初始化每次最多加载4096条，超过范围明确终止，不静默遗漏旧历史；
超大旧会话需另行有界重建，不能直接宣称自动迁移完毕。

## 4. 尚未完成的后续范围

- 80%/60%、最近6轮和摘要输出大小尚未做长对话规模调优，
  并非所有请求都能保持6轮或达到60%；摘要有损且会增加触发请求延迟。
- 关键词召回提供基础能力；专用日期/菜品索引、复杂跨会话指代、
  语义检索排序不在本次交付中。歧义仍应澄清，不能猜测历史对象。
- 原设计第三阶段的画像逐字段版本、发布前外部画像变更校验、
  选择性遗忘/物理清理及旧检查点失效代次尚未实现。
  当前保留已有画像更新确认及整会话回收站/到期清理，不宣称这些增强已经完成。
- 当前状态中移除原文不删除旧检查点的历史副本，也不保证数据库立即缩小。
  本次未新增检查点历史保留策略。
- 开发 `InMemorySaver` 不具备跨进程持久恢复保证；
  数据库检查点验收针对 PostgreSQL 模式，原文重建不能恢复丢失的写入批准。
- 未进行持续负载、规模化摘要质量或多模型对照验收；未部署到正在运行的服务。
