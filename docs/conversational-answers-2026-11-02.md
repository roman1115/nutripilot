# 自然回答与多轮问答改造

日期：2026-11-02。状态：实现和本轮验收已完成；真实模型严格检查 8/9，仍有一轮预算降级，未全部通过。

## 目标与边界

解决只有推荐卡片、解释套画像、做菜问题再次推荐的问题。保留 Python、LangGraph、
FastAPI、React/TypeScript、MCP、独立持久 Worker 和现有安全边界。
没有新增依赖、模型服务、Agent 或 Worker；没有修改 100 道菜谱及整菜营养计算口径。

## 实现

- Intent 新增 `FOOD_QUESTION`、`CONVERSATION`，区分解释、比较、烹饪原理和非任务回应。
  具体完整做法仍是 `RECIPE_QUERY`，具体营养仍是 `NUTRITION_QUERY`。
  已知独立简短感谢有确定性保护，不能被上一轮问题带偏，也不表示写入批准。
- Planner 复用既有工具和白名单；领域问答仅允许按需读取做法、营养、指南，
  已有资料足够或通用原理不强制检索。感谢直接到回答，不调用工具。
- 回答获得当前问题、最近最多 8 条消息的摘要、实际展示顺序及最多 6 条、16,000 字符历史证据。
  历史资料只解释已经讨论的菜，不能充当本轮新推荐的检索结果。
  比较所需配方按需读取，未指定比较维度时优先补齐前两道原始配方；
  查询多个菜的做法或营养，不覆盖用户看到的推荐顺序。
  同时保留当时已发布的推荐理由，后续解释不能事后编造另一个排序依据。
- `RecommendationAgent` 生成自然正文与理由，原始工具结果仍由既有 grounding 规范化。
  确定性检查拦截未知推荐、引用、无依据具体数量和部分个人/医疗论断；
  再经相同网关的一次独立语义审核，拒绝最多修正一次，随后使用原有事实降级。
  审核以规范化事实为依据，不能把降级正文误当作唯一答案。
  修订输入包含被拒绝的原稿 `answer_to_revise` 和反馈；审核当前修订时不混入旧原稿。
  过敏原列表为空只表示未标注，不允许改写为“不含常见过敏原”。
- 已审核正文绑定完整规范化结果的 SHA-256；最终安全过滤改变菜品、营养、引用或警告后，
  不再复用旧解释。输出再次扫描正文、卡片理由和建议中的医疗论断。
  部分菜品被删除时重建正文并删除相关 `meal:`/`recipe:` 来源。
  Trace 记录 `approved_prose_applied`，验收同时检查审核通过与最终正文实际发布。
- 单轮时间与 Token 预算不变。审核阶段 Token 不够时，保留已经取得的可靠事实，
  不发布未审核文字；执行超时和 Worker 归属丢失仍按原机制终止。
- 前端纯文本按空行拆段，用 React 文本节点显示，不引入 Markdown 依赖或执行 HTML。
  问答与感谢不强行展示推荐卡片；刷新恢复使用既有持久消息，不是前端缓存替代后端任务。

## 复跑

脚本使用独立验收用户及会话，复用原服务；每次使用新报告名，不覆盖既有失败证据。
真实模型调用会产生费用。以下命令不包含启动服务：

```bash
.venv/bin/python scripts/verify_conversational_answers.py \
  --api-url http://127.0.0.1:8006 \
  --web-url http://127.0.0.1:5178 \
  --executable '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
  --output .runtime/natural-answers-real-2026-11-02-rerun-01.json

NUTRIPILOT_TEST_EXTERNAL=1 .venv/bin/pytest -o addopts='' -q
.venv/bin/ruff check .
.venv/bin/mypy src apps scripts/verify_conversational_answers.py
```

## 限制

一次模型审核不是确定性事实证明，可能误拒绝或漏判；通用烹饪知识也可能存在语义错误。
具体数字检查不能独立证明对象与单位正确，仍须审核及实际内容检查。
自然回答正常增加一次审核调用，修正时最多再增加生成和审核各一次，耗时及费用会增加。
有界摘要不是无限上下文或长期语义记忆。历史已保存回答不会自动改写。
没有进行生产负载、完整应用镜像、公开部署、营养实测或完整备份恢复演练。
