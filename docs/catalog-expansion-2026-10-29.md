## 自动草稿

新增 `scripts/draft_food_catalog.py`，复用导入器及现有数据模型，不调用模型或引入依赖：

- 仅为唯一食材、唯一数字用量、已有换算且六项成分与现有安全元数据齐备的行给出建议。
- 长别名优先，避免把“酱油”中的“油”映射成食用油；保留数值范围。
- 缺失或冲突用量、未识别单位、多义别名、不同换算比例、可选项、腌制用料及蛋清/蛋黄等保留异常，不强行采纳。
- 列出步骤中的定量投料和可食部/排除项检查提示，供维护者交叉核对；不自动推断实际吃入量。
- 所有草稿都保留 `issues`。不改线上数据，不直接进入推荐，输出路径已存在则拒绝覆盖。

实际对本批固定来源生成草稿：50 道、370 条用量文本，218 条有建议（58.9%），152 条无建议。建议也必须核对，最终映射不与草稿逐行一一对应，步骤补料另计。此数据不能解读为准确率、无人审核完成率或节省时间比例；本轮没有计时对照实验。

重现命令：

```bash
.venv/bin/python scripts/draft_food_catalog.py \
  --howtocook-repo .runtime/data-sources/HowToCook \
  --start-index 50 \
  --output .runtime/catalog-batch2-draft-new.json
```

扩充过程是维护者工作流。普通用户对话和查询期间无需填写映射或审核数据。

## 重要整理选择

| 菜谱 | 已记录的处理 |
| --- | --- |
| 肉蛋盖饭 | 清单熟米饭与步骤干米冲突，明确采用熟饭 240 克；保留 4 蛋和 300 克肉的整份配方，不按“一人份”缩小 |
| 可乐炒饭 | 计入 3 个蛋；无豆瓣酱版本按原文追加老抽，共 12.5 毫升；使用普通含糖可乐 |
| 清蒸生蚝 | 清单和步骤冲突，采用步骤总蒜 60 克、酱油 30 毫升；每蚝可食肉 20 克是项目默认 |
| 红烧鲤鱼 | 约 1 千克整鱼按项目 50% 可食率折 500 克鱼肉；假设吸油为净鱼重 5%～10%，计 25～50 克，另计底油 10 克，炸锅油排除 |
| 微波葱姜黑鳕鱼 | 用裸盖鱼记录，区别于普通鳕鱼；蒸液和捞出的葱姜排除，装盘淋入的花生油全量计入并保留现有花生过滤 |
| 蒜蓉空心菜 | 采用 USDA 空心菜对应记录；两次锅油合计原文 45 毫升，不重复添加 |
| 蒲烧茄子 | 自调蒲烧汁全部浇入，全部计入；蜂蜜及白糖体积用明确的项目密度换算 |
| 勾芡香菇汤 | 成菜盐 3 克；泡洗盐 2 克排除；总水 350 毫升包含调淀粉的 50 毫升 |
| 红烧鱼、瘦肉土豆片 | 分别明确采用鲤鱼、小葱项目替代版本，不将其声称为原文鲫鱼或蒜苗的精确营养 |
| 意式肉酱面、印度土豆花菜等 | 明确菜系随配方传入检索餐食，避免统一写“中式”造成偏好解释错误 |

其余默认量、可食率、品牌替代、可选项及子配方全部保存在逐菜映射中，并进入既有计算说明。常规炒油全量计入；弃腌料不计主体营养，但已映射的接触过敏原继续保留。复合食品的保守潜在过敏项不是品牌检测结论。

## 来源与元数据

仍使用 HowToCook 提交 `308cc8b7dab1da84b20e7fafdf836a715437f582` 和原有 USDA/MEXT/CJ 固定数据。重建检查上游许可证文件与逐文件哈希，本轮没有更新外部来源或重新下载营养数据。

新增菜谱检查了原文及额外引用。猪油拌饭包含 Wikipedia 说明链接，煮锅蒸米饭包含视频链接；这些外链未被抓取、复制或用作营养依据。本轮不导入图片或第三方网页，也不以仓库 Unlicense 推断外链的授权。后续新增来源仍需独立核对复用权利。

`source_calories_text` 原样保留来源预估文字，`source_calories_kcal` 只解析单值千卡。缺失、范围、其他单位保持未知；不会给六项营养缺失值兜底。当前 100 道都有来源单值卡路里，但不假设它与本项目所选投料版本一致。`tools` 为已识别工具名集合，完整文本仍保留在 `raw_ingredients`。

## 实际验证

- 完整后端测试 **203 项通过**，1 条既有依赖警告。覆盖草稿门槛、异常用量、别名冲突、来源元数据、实际第二批投料与吸油区间、接触过敏原、来源变更拒绝、API/MCP/对话及完整餐单候选门槛。
- 修正一个既有安全测试的日期输入：测试构造的餐单日期通过用户消息显式传入，避免本机日期与配置时区跨日时先触发日期错误；安全校验保持不变。
- Ruff 通过；按项目 `MYPYPATH=src` 设置运行 mypy，**95 个源文件通过**，含两个导入/草稿脚本。前端 typecheck/build 通过。
- Fake 核心回归 **60/60**，扩展回归 **8/8**，报告在 Git 忽略的 `.runtime/catalog-batch2-evals/`；使用 Fake 模型、Hashing 向量及 Lexical 重排，不代表真实 Qwen/BGE 效果。
- 固定本地源与映射重建 100 道成功；在 `data/` 重复导入内容一致。原有 50 道结果及所有来源成分数值的稳定性检查通过。
- 实际 HTTP 两库统计：7,802 条成分、111 条中文映射说明、100 道可计算、0 待整理、44 道含用量范围。新增配方详情保留来源卡路里及独立计算区间。
- Chrome 桌面 1440×1000 和手机 390×844 实际发送“午餐推荐红烧鲤鱼”，显示整道菜热量 **1741.6～1962.6 千卡**、投料重量区间和单道菜提示；无页面横向溢出或 JavaScript 错误。截图为 `.runtime/catalog-batch2-desktop.png`、`.runtime/catalog-batch2-mobile.png`，临时服务验证后停止。

## 当前边界

100 道 `calculation_ready` 表示本项目所选投料版本可计算；不等于原作者唯一配方、营养师审核或实际成菜检测。整菜总量可较大，不能当作个人单次摄入量。可食率、密度、自然单位和吸油量仍有项目假设；未建模烹调损失、腌料吸收、酒精挥发或成菜重量。

本轮未重新验证真实 Qwen/BGE、PostgreSQL/Qdrant 或 Docker 完整构建。独立过敏原库、独立数据库表和在线审核后台未实施；完整一餐仍依赖原有 18 条未独立核验的演示餐食。
