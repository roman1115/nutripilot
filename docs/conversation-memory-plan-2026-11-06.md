## 一、当前实现核对

- `src/nutripilot/application/chat_service.py` 在新一轮中追加上一轮双方消息，
  保留最近8条；用户正文截至2000字符，助手正文截至3000字符。
- `src/nutripilot/memory/context.py` 的 `compact_messages` 将近期消息拼接并截断，
  不是融合旧摘要的滚动语义摘要；没有摘要覆盖位置或版本。
- 当前 `recommendation-v58` 通常读取最近4条消息，有近期消息时不提供摘要。
  做法查询和通用问答进一步只保留最多2条用户消息、清空摘要；
  闲聊仅传当前问题和意图。因此存在助手历史不可见、追问承接不足的风险。
- 已有会话持久化、结构化槽位、讨论菜品、工具证据、用户画像与反馈。
  历史记录持久化不等于模型能检索历史；这些能力也不等于完整长期会话记忆。
- 本次只核对相关源码，未运行新一轮模型请求或测试。

## 三、方案方向

### 1. 近期原始对话

- 保留近期双方对话，不因通用问答或闲聊机械删除助手内容。
- 初始讨论目标为最近6个完整轮次；这是待实测参数，不是已配置值或固定保证。
- 从最新完整轮次向前选择，避免只保留问题而丢掉对应回答。
- 当前问题始终保留；超长消息另行处理，不以截断后冒充完整上下文。
- 意图识别、规划、回答共享基础上下文和覆盖位置，各自追加必要的任务资料。
  修复承接时仍应避免历史配方污染或助手旧说法变成事实证据。

### 2. 会话滚动摘要

- 旧对话退出原文窗口前，先与旧摘要融合并成功保存。
- 保留用户目标、适用时间与范围、讨论对象及顺序、已确认或否定的决定、
  待办与未解决问题、更正，以及助手已解释或建议的内容。
- 区分用户陈述、助手建议、工具已验证事实；不得把助手建议升级为事实，
  不把“今天不吃辣”变成永久偏好。
- 保存来源消息编号、摘要覆盖位置及版本；摘要和覆盖位置原子更新。
  具体字段和存储位置留待实施时确定，不单靠消息条数充当稳定游标。
- 使用版本校验避免旧后台任务覆盖新摘要；重试不能重复推进覆盖位置。
- 摘要本身控制长度，压缩后仍需保留来源，避免摘要随会话无限增长。
- “摘要或原文覆盖消息”是覆盖范围要求，不代表摘要保留了全部语义细节。

### 3. 按需历史召回

- 复用数据库按会话、时间、关键词或菜品编号查询原文，
  返回少量相关片段、必要前后文和来源编号；首期不新增向量库或独立服务。
- 默认当前会话；用户明确询问其他历史会话时，仅查询其本人可用会话。
- 早期做法、营养等具体事实仍回原工具核实，不用旧助手回答作为事实证明。
- 历史正文、摘要及工具内容均作为数据，不能成为系统指令。

### 4. 跨会话用户记忆

- 复用用户画像和显式反馈，管理稳定偏好、忌口、过敏原、厨具等，
  补充适用范围、来源及更新时间；具体字段待实施核对。
- 临时需求留在当前会话；长期更新沿用现有确认机制。
- 不推测用户疾病或过敏，不混淆用户过敏原与食品自身过敏原。
- 支持查看、修改和删除；用户更正或删除后，旧摘要不能自动把旧信息写回画像。
- 会话回收站、恢复、七天到期清理与相关摘要、召回索引的生命周期保持一致。
  显式保存的用户画像属于独立数据，删除会话不自动等于删除画像，
  需区分用户要求删除的对象，并防止已删除会话参与召回。

## 四、预算讨论补充

xerina 指出：如果工具结果逐轮累积，近期对话可用空间会不断缩小。
方案必须明确避免这一点：

- 工具结果可以持久化，但每轮只注入当前任务有关的字段和对象，
  不把全部历史工具结果持续追加到模型输入。
- 同一对象的重复结果按来源和版本选择，避免重复；
  用户要求比较版本时才同时提供，不能盲目覆盖历史。
- 推荐后追问第二道做法，只提供该菜的相关配方；
  转为通用原理时移除无关菜谱和营养资料；再次比较时按编号补取事实。
- 为近期对话预留基本空间，并给工具资料单独的额度；工具超限时优先筛选、
  分批读取或按需查询，不能默认继续挤掉近期对话。
- 按当前任务资料量动态调整，不应因聊天轮数增加而自然缩短近期窗口。
- 预算计算包含系统提示词、工具定义或结构契约、当前问题、画像、摘要、
  原文、召回片段和工具结果，预留回答输出、后续必要调用及估算余量。
  同时检查单次模型窗口和整轮 Agent 累计预算。
- 复用现有 token 估算和用量记录能力；不是按字符或消息条数直接等价换算。
  此前3000/1000 tokens等数字仅是解释示例，不是正式配置。

压缩应提前触发，必要时在读取前补做；失败不推进覆盖位置、不删除原文。
若实际超预算，不能声称上下文完整：记录缺失范围，优先按需召回或明确澄清。
超长输入和持续压缩失败时的具体处理仍待实现设计与测试，不承诺无限上下文。
后台维护复用现有 Worker，具备重启重试及执行归属保护，不采用无持久化的裸后台任务。

5. 同步调用方、数据模型、迁移、持久化实现、Fake、测试及文档；

重试与重启、跨用户隔离、删除与回收站恢复及到期清理。
