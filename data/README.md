# 菜谱与食材营养数据

## 当前内容

| 文件 | 内容 |
| --- | --- |
| `ingredients.json` | 7,802 条记录：7,793 条 USDA、8 条日本官方成分表、1 条 CJ 味精规格数据；每 100 克六项营养，未知值保留 `null` |
| `recipes.json` | 50 道 HowToCook 来源菜谱，保存食材原文、用量原文、操作步骤及文件校验和 |
| `sources.json` | 来源、许可证、固定版本、下载地址与校验和范围 |
| `catalog_selection.json` | 固定的菜谱文件清单、源版本和初始中文食材映射 |
| `recipe_mappings.json` | 逐菜谱映射、来源哈希、默认用量、单位换算假设、范围、排除项及异常原因 |
| `supplemental_ingredients.json` | 9 条增补成分记录的固定快照，保存来源、原始数字文本及提取说明 |
| `catalog_report.md` | 导入器生成的50道菜谱整理结果，可查看每道菜的说明或具体缺口 |
| `meals.json` | 保留的 18 条旧演示餐食；编号与现有计划、反馈继续兼容 |

7,802 是源数据食品条目数，不是 7,802 种已核对的中文基础食材。当前 86 个条目有中文映射说明，其中 77 个用于可计算配方的食用投料。不能以名称相似自动判断生熟状态、食材品种、品牌或可食部一致。项目选定的通用替代、品种近似及其限制写在映射说明中，不冒充原作者指定产品。

50 道菜全部达到 `calculation_ready`，原先剩余 25 道已补齐，待整理为 0；24 道存在用量范围。`calculation_ready` 表示计算所需数据或显式项目假设齐全，不表示营养师审核、实际试做或成菜检测通过。加上原有 18 道演示餐食，当前载入 68 条餐食记录；不等于 68 份完整一餐。餐单检索会在排序和截断前筛选 `complete_meal`，不会让单道菜挤占完整餐食候选。

## 来源

- USDA FoodData Central SR Legacy，版本 `2018-04`；直接使用官方 CSV 下载包，不要求用户配置 API Key。数据许可证为 CC0-1.0，保留 FDC 编号、英文原始名称和来源链接。许可依据：`https://fdc.nal.usda.gov/api-guide.html` 的 Licensing 说明。本版本是固定历史数据，不声称使用最新食品数据。
- HowToCook，提交 `308cc8b7dab1da84b20e7fafdf836a715437f582`。上游仓库标注 Unlicense，许可证副本在 `licenses/HowToCook-Unlicense.txt`。保留逐文件链接和 SHA-256；本轮没有导入图片、其他文件或整站爬虫数据。未来复用新来源仍需检查各文件的额外来源说明。
- 日本文部科学省《日本食品標準成分表（八訂）増補2023年》，使用 2026-03-27 发布的官方 XLSX，提取去皮土豆、土豆淀粉、充填嫩豆腐、熟松子仁、韭菜、干紫菜、小型海虾和鸭皮蛋。依官方说明注明出处后可复用，不标为 CC0。出处：日本食品標準成分表（八訂）増補2023年から引用。
- PT. CJ Indonesia 2018-01-18 味精规格书第 2 页，供应商托管副本。仅保存营养数值事实与出处，不再发布原 PDF，不宣称原文档开放授权。托管文件名含 ajinomoto，实际厂商是 CJ；游离谷氨酸 78.6 克不能当作蛋白质，使用营养表粗蛋白 0 克。

增补来源校验和、引用要求和测量口径详见 [来源说明](licenses/nutrition-source-notes.md)。MEXT 原表 `(0)` 是来源推定零，保留在 `source_nutrient_values` 中，与缺失值 `null` 区分；不同来源的能量、纤维测定口径未统一，尤其生土豆纤维含抗性淀粉，不能据此推断熟土豆。

## 本批项目版本

- 料酒用通用含盐烹调用酒，鸡精用干鸡汤粉，挂面用含盐干小麦细面；老抽和蒸鱼豉油明确改通用酿造酱油。复合食品采用指定通用记录，不表示任意品牌或中国原菜谱的精确营养。
- 白灼虾选不蘸料版本；250 克带头壳虾按来源 50% 可食率折 125 克。清蒸鱼默认整鱼 600 克、可食率 50%，是项目假设；蒜蓉虾每只整虾 20～30 克，保留范围。
- 葱油拌面只分摊实际拌入的 15 毫升酱汁；成品总量 180～199 克、密度 1.05～1.2 克/毫升是明确项目假设。蒜蓉酱按 50 克子配方展开；综合香料按 3 克项目配比展开。三者都不是原品牌配方或实测产率。
- 皮蛋豆腐原文的香油、辣椒油、花生等明确为可选，按约定默认不加。原始用量和步骤保留，选择的项目版本在计算说明和对话警示中可见。
- 金针菇汤等原文高盐投料照录，不为达成营养目标修改来源；范围只覆盖记录的投料不确定性，不涵盖品牌差异、烹调损失或所有误差。

## 计算与发布

- 每道配方引用 `ingredient_id`，按 `各食材每100克营养 × 投料克重 / 100` 汇总。默认 `calculation_basis=whole_recipe`，计算整道菜，不除以人数；`servings` 仅为可选说明。兼容显式 `per_serving` 的调用方，但必须提供人数。
- “个、瓣、适量、毫升”可采用已记录的换算或项目默认值；例如每个去壳鸡蛋50克、每瓣蒜4克、菜籽油每毫升0.92克均为项目假设，不是原菜谱或实测证据。不能把缺失的营养字段当作零。
- 原文范围保留为 `grams_range`；营养结果的 `nutrient_ranges` 按各项投料上下限汇总，固定用量则上下限相同。这是保守投料区间，不是统计置信区间。兼容数值字段等于上限，不能当成精确值或中间值。热量上限筛选采用区间上限，蛋白质下限筛选采用区间下限。
- 可选项默认不加，存在明确原文默认做法时按配方说明选择。用量清单及操作步骤交叉检查；重复出现的同一次投料不重复计入。
- 普通炒菜全部投料油计入；油炸菜只计 `quantity_basis=oil_absorption` 对应的吸油量范围，炸锅油作为排除项。当前50道来源菜谱尚无采用该吸油量规则的独立油炸配方，吸油规则已用测试验证，不声称实测通过。
- 焯水、腌制液、独立蘸料不计主体菜营养；明确拌入、淋入菜中的汁属于配料，计入。煮制产生的汤汁不额外加营养，也不扣减弃汤中的食材营养损失。加工用水需要排除原因；投料重量不是成菜重量。
- 过敏原库及新的提醒机制留待后续。现有接触过敏原过滤保留：排除腌料营养不能删除其已知过敏原。未知过敏原仍为 `null`，不会自动变成“无”；空列表仅表示当前食材记录没有列出本项目关注项，不是无过敏保证。
- 输出状态为 `calculated_estimate`。未校正烹调损失、吸水、蒸发或油盐残留；显示的是投料重量，不能标为成菜重量或营养检测值。
- 包括糖拌西红柿在内全部新配方默认按整份显示（其能量由旧版每人份56.7千卡改为整道菜113.4千卡）。单道菜、主食、汤和加餐不能由现有餐单规划器直接充当完整一餐。
- 新配方未知的价格与总准备时间保留为 `null`；指定价格或时间上限的检索不会把未知值作为零而通过。

启动时，两库由同一载入器校验。完整配方转换为既有 `Meal` 契约，因此离线模式可直接检索，外部模式沿用 PostgreSQL 餐食保存和 Qdrant 建索引流程。源食材、源菜谱暂以版本化 JSON 保存，尚未迁移成可在线编辑的独立数据库表。

## 查询

以下是已有访问控制保护的只读 API，可在 `/docs` 调试：

- `GET /api/v1/catalog`：数据量、可计算/待处理数量及来源。
- `GET /api/v1/ingredients?q=西红柿&limit=30&offset=0`：食材名称与别名查询、分页。
- `GET /api/v1/ingredients/fdc:170457`：单条营养记录与来源。
- `GET /api/v1/recipes?status=pending`：查看需要继续整理的菜谱。
- `GET /api/v1/recipes/1004`：原始配方、来源和可复算营养。

已接入现有 MCP `search_meals` 与 `get_nutrition`；可以在对话中查询“糖拌西红柿的营养”。尚未提供在线审核后台、配方编辑或新的 Agent 工具。

## 重现导入

先把上述 USDA ZIP 下载到本地，并获取含固定提交的 HowToCook Git 仓库。下载包的 SHA-256 必须与 `catalog_selection.json` 一致：

```bash
.venv/bin/python scripts/import_food_catalog.py \
  --usda-archive .runtime/data-sources/usda-sr-legacy-2018-04.zip \
  --howtocook-repo .runtime/data-sources/HowToCook \
  --output .runtime/catalog-rebuilt
```

脚本校验下载包哈希、营养单位、重复记录、引用和计算门槛后再生成文件。增补快照随仓库保存，按 `catalog_selection.json` 的 `supplemental_sha256` 校验；重建无需在线下载原 XLSX/PDF，更新快照必须核对原始证据并更新哈希。增补快照不得包含替换来源菜谱。

逐菜谱映射与原文件 SHA-256 绑定；原文发生变化或映射清单缺项时拒绝重建，避免旧映射悄悄套到新菜谱上。相同内容可重跑；发现目标文件与新结果不同则拒绝覆盖，应先导出到新目录并审查差异，防止覆盖已整理的配方。

这是可复用的规则化批量重建流程，不是对任意陌生菜谱自动理解并核验的通用爬虫。新增菜谱需补一条映射或具体异常记录；同种食材、单位换算规则可复用。原文与项目假设分开保存，不需要普通用户参与填写。
